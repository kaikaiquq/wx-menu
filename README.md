<h1 align="center">两人菜单</h1>

<p align="center">情侣共同空间微信小程序：一起维护菜单、发送心愿、聊天互动、回应并记录约定。</p>

## 项目简介

两人菜单面向情侣场景，支持视频、甜点、饮料、正餐、小食和约会惊喜等自定义内容。点单条件不局限于金额，也可以是“一个抱抱”“你来选电影”等约定。

技术栈为微信原生小程序 + 微信云开发。用户资料、个人内容库、共同空间、心愿单、聊天和点单记录均保存在云端。

## 主要功能

- 微信登录，自主选择头像、昵称和性别
- 女性粉色 / 男性灰蓝双主题
- 独立个人内容库
- 邀请码绑定情侣（复制或分享卡片）
- 绑定后创建空白共同空间
- 从个人库导入，或「新建并加入」共同空间
- 共享留言簿
- 心愿单、点单、回应与完成闭环
- 消息 Tab：对象会话置顶、好友私聊、群聊
- 前台跨页新消息轻提示、消息未读角标（云端实时监听，无定时消息轮询）
- 位置 Tab：原生地图展示双方位置，默认看 TA；进入时自动申请授权，同意后跨页面共享前台实时位置
- 好友系统：用用户 ID 添加 / 删除好友
- 分类 / 菜单管理与图片上传
- 解绑清空共同空间，个人内容不受影响

## 数据模型

### 个人内容库

- 每个用户独立的 `userConfigs`
- 绑定 / 解绑不会改写个人内容

### 情侣共同空间

- 每次绑定创建新的 `coupleId`
- 初始菜单、心愿、留言、订单为空
- 解绑后共同数据清空且不可恢复

## 技术栈

- 微信原生小程序（JavaScript / WXML / WXSS）
- 微信云开发（云函数、云数据库、云存储）

## 开始使用

1. 安装微信开发者工具，注册小程序并开通云开发。
2. 在开发者工具中把 AppID 换成自己的。
3. 将云环境 ID 写入 `config/cloud.js`：

```javascript
module.exports = {
  envId: '你的云环境 ID',
};
```

4. 按 [云开发开通与部署](./docs/cloud-setup.md) 创建数据库集合并部署五个云函数，单独配置 `chatSignals`、`coupleLocations` 的读取权限。
5. 编译预览即可，**无需构建 npm**。

## 消息通知

前台由一个应用级监听订阅当前用户的 `chatSignals` 文档；真正发生变化才合并读取未读摘要。切到其他页面仍可收到轻提示，后台主动断开、回前台补齐未读，异常时有限重连或手动重试，不退回轮询。

详细方案、费用边界和部署后的双账号检查见 [消息通知评估与实现方案](./docs/chat-notifications.md)。此功能不等同于退出小程序后的微信服务通知；后者需要真实订阅模板与用户授权，尚未接入。

本地逻辑测试：`npm test`（Node.js 18 或更新版本，无需额外测试依赖）。云端权限、实时连接和多端兼容仍需在部署后真机验收。

## 位置共享

底部五个 Tab 为「今天 / 点单 / 位置 / 消息 / 我们」。进入位置页默认展示 TA，双方通过原生地图标记区分。首次进入自动检查隐私和位置权限，同意后开始微信前台持续定位，跨页面仍可更新；云端仅保存最新坐标，通过 `watch` 推给对方，不定时拉取位置。用户手动停止后，切回页面不会自行重新开启。

位置权限不能默认代用户同意。需在公众平台开通实际类目允许的定位接口、完善隐私指引；双方各自授权才能共享各自位置。退后台只保留最后位置，本次不支持后台持续定位。详细方案、节流成本、部署与双真机验收见 [实时位置共享方案](./docs/location-sharing.md)。

## 核心流程

1. 各自维护「我的内容库」
2. 一方生成邀请码，另一方加入并填写纪念日
3. 向共同空间导入或新建内容
4. 点单 → 回应 → 完成心愿
5. 需要时可解绑；共同空间清空，个人库保留
